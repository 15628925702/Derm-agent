# DermAgent 使用规范

本文档只描述当前推荐的运行方式：

- 三个数据集分别切到各自的专用分仓
- 使用各自的专用经验库
- 全部走手工规则（heuristic）
- 不打开 `candator` / candidate policy / learned 组件

这里的“**不打开 candator**”统一理解为：

- 不使用 candidate policy
- 不使用 learned controller
- 不使用 learned retrieval reranker
- 不使用 learned evidence calibrator
- 不切到任何 `candidate_*`、`learned_*` 的策略文件

---

## 一、总原则

### 1. 每个数据集必须切到自己的分仓

不能混用：

- `DERMAGENT_POLICY_ROOT`
- `DERMAGENT_SPLIT_STATE_ROOT`

必须保证：

- `PAD-UFES-20` 用自己的默认主仓
- `HAM10000` 用 `ham10000_v2`
- `ISIC2019` 用 `isic2019_v1`

### 2. 全部使用手工规则

当前推荐运行配置：

- `controller_family = heuristic`
- `enable_learned_retrieval_reranker = false`
- `calibrator_mode = heuristic`

### 3. 不打开 candator

不要使用：

- `candidate_policy.json`
- `controller_sparse_candidate_policy.json`
- `candidate_stage*`
- `learned_*`
- 任何训练产物目录里的 candidate policy

如果手动传 `--policy-config`，只允许传当前稳定 heuristic policy。

## 二、三个数据集的分仓

### PAD-UFES-20

说明：

- 这条线当前使用默认主仓
- 默认主仓里当前 stable policy 仍然保留旧主线 `policy_id` 名字，但运行配置已经是 heuristic
- 评测时必须显式传 `split_sanity.json`

数据：

- 数据根：`/root/DermAgent/data/pad_ufes_20`
- policy root：`/root/DermAgent/state/policy`
- split state root：`/root/DermAgent/state/split_states`
- split json：`/root/DermAgent/outputs/overnight_eval_bundle/split_sanity.json`

切仓方式：

```bash
cd /root/DermAgent
export DERMAGENT_POLICY_ROOT=/root/DermAgent/state/policy
export DERMAGENT_SPLIT_STATE_ROOT=/root/DermAgent/state/split_states
```

### HAM10000

说明：

- 只用 `ham10000_v2`
- 不用 `ham10000_v1`

数据：

- 数据根：`/root/DermAgent/data/ham10000`
- policy root：`/root/DermAgent/state/dataset_adaptation/ham10000_v2/policy`
- split state root：`/root/DermAgent/state/dataset_adaptation/ham10000_v2/split_states`
- split json：`/root/DermAgent/outputs/dataset_adaptation/ham10000_v2/ham10000_split.json`

切仓方式：

```bash
cd /root/DermAgent
source /root/DermAgent/state/dataset_adaptation/ham10000_v2/experiment.env
```

### ISIC2019

## 六、严格禁止的用法

不要这样做：

- 不要切到 `candidate_policy.json`
- 不要切到 `candidate_stage*`
- 不要切到 `controller_sparse_candidate_policy.json`
- 不要使用训练输出目录中的 candidate policy
- 不要把 `ham10000_v1` 当作当前推荐线路
- 不要把 `HAM10000` / `ISIC2019` 跑在 PAD 的默认主仓里

---

## 七、常见报错

### 1. `unrecognized arguments` / `bash: --data-split: 未找到命令`

原因：

- 反斜杠 `\` 后面有空格

错误示例：

```bash
--limit 12 \ 
```

正确：

```bash
--limit 12 \
```

### 2. `Metadata CSV not found`

PAD-UFES-20 必须显式传：

```bash
--split-json /root/DermAgent/outputs/overnight_eval_bundle/split_sanity.json
```

### 3. 跑出来像是用了别的数据集经验库

先检查：

```bash
echo $DERMAGENT_POLICY_ROOT
echo $DERMAGENT_SPLIT_STATE_ROOT
```

如果和当前数据集不匹配，说明没切仓成功。

---

## 八、推荐运行顺序

如果要顺序跑三个数据集，推荐：

1. `PAD-UFES-20`
2. `HAM10000`
3. `ISIC2019`

每跑一个数据集前，都重新执行一遍对应的切仓命令。
