# DermAgent 数据集接入设计

本文档用于约束后续新数据集接入方式，目标是把数据集接入从“散落的手工改造”收敛成统一 contract。

## 1. 当前状态

当前已经有专用 loader 的数据集：

- `ham10000`
- `isic2019`
- `scin`
- `sd198`

当前本地 `data/` 下尚未正式接入的数据集：

- `dermnet`

初步判断：

- `SCIN`：已完成接入，当前作为 exploratory 扩展数据集
- `SD-198`：已完成接入，当前结论是 `grouped` 路线比 `full-label` 更合理
- `DermNet`：当前不建议直接接入，只有索引与版权相关元数据，缺少可直接安全使用的本地图像资产闭环

## 2. 接入目标

每个新数据集接入后，至少要支持：

1. `load_<dataset>_case_input_by_index(...)`
2. `load_<dataset>_case_inputs(...)`
3. 可被 `dataio/case_loader.py` 注册和路由
4. `CaseInput.dataset_name` 正确
5. `CaseInput.label_space_id` 明确
6. metadata 做过防泄漏清洗
7. 可用于 split / compare / bootstrap 主流程

## 3. 推荐 loader contract

每个专用 loader 文件建议至少提供以下接口：

```python
DEFAULT_<DATASET>_ROOT: Path

def discover_<dataset>_assets(data_root: str | Path = DEFAULT_<DATASET>_ROOT) -> dict | dataclass: ...

def load_<dataset>_rows(data_root: str | Path = DEFAULT_<DATASET>_ROOT) -> list[dict[str, Any]]: ...

def standardize_<dataset>_row(
    row: dict[str, Any],
    *,
    data_root: str | Path = DEFAULT_<DATASET>_ROOT,
) -> <DatasetCaseRecord>: ...

def load_<dataset>_record_by_index(
    case_index: int,
    *,
    data_root: str | Path = DEFAULT_<DATASET>_ROOT,
) -> <DatasetCaseRecord>: ...

def load_<dataset>_records(
    *,
    data_root: str | Path = DEFAULT_<DATASET>_ROOT,
    limit: int | None = None,
    offset: int = 0,
    sample_size: int | None = None,
    seed: int = 0,
    shuffle: bool = False,
) -> list[<DatasetCaseRecord>]: ...

def load_<dataset>_case_inputs(
    *,
    data_root: str | Path = DEFAULT_<DATASET>_ROOT,
    limit: int | None = None,
    offset: int = 0,
    sample_size: int | None = None,
    seed: int = 0,
    shuffle: bool = False,
) -> list[CaseInput]: ...

def load_<dataset>_case_input_by_index(
    case_index: int,
    *,
    data_root: str | Path = DEFAULT_<DATASET>_ROOT,
) -> CaseInput: ...
```

## 4. `CaseInput` 最低要求

每个 loader 产出的 `CaseInput` 至少应满足：

- `case_id`：稳定、唯一
- `image_path`：本地可解析路径
- `metadata`：已去除泄漏字段
- `label` / `reference_label`：原始标签或当前实验标签
- `dataset_name`：固定且小写风格一致，例如 `ham10000`、`isic2019`、`scin`
- `label_space_id`：显式设置，不依赖猜测
- `source_metadata_path`：可追溯

## 5. `case_loader.py` 中的注册规范

新数据集接入后，应在 `dataio/case_loader.py` 中统一注册：

```python
register_dataset_loader(
    "scin",
    load_by_index=load_scin_case_input_by_index,
    load_all=load_scin_case_inputs,
    data_root=DEFAULT_SCIN_ROOT,
)
```

要求：

- 尽量直接传专用 loader 函数
- 专用 loader 函数应支持 `data_root=...`
- 不再为新数据集增加额外 legacy hardcode 分支

## 6. metadata 清洗规范

每个数据集都必须显式梳理 metadata 泄漏风险。

最低检查项：

- 真值标签列
- one-hot 标签列
- 任何直接等价于 diagnosis 的字段
- `ground_truth` / `target` / `label` / `dx` 等命名变体

如果新数据集有特殊风险字段，需要同步更新：

- 该数据集 loader 内部的 metadata 清洗逻辑
- 必要时更新 `agent/state.py` 中的全局 `LEAKY_METADATA_KEYS`

## 7. label space 要求

新数据集接入时必须回答：

1. 原始标签空间是什么
2. 是否直接沿用原始标签空间
3. 是否需要 aligned subset / 聚合标签空间
4. 哪些标签属于 malignant / benign / uncertain

如果当前仓库没有对应 label space，需要在：

- `agent/label_space.py`

中补注册逻辑。

## 8. 优先接入顺序建议

### 第一优先：SCIN

原因：

- 已有官方镜像 CSV
- 图像路径明确
- metadata 丰富，适合 workflow-aware 研究
- 可以自然支持“多图 + 症状 + 人群特征”的 workflow 扩展

主要挑战：

- 标签不是传统单标签分类格式
- `weighted_skin_condition_label` 需要解析
- 可能需要先定义一个可评测的标签子空间

### 第二优先：SD-198

原因：

- 本地数据完整
- 图像和标签文件结构清晰
- 可作为长尾、多类数据集扩展验证

主要挑战：

- 198 类太大，不适合直接照搬当前主线
- 需要先定义标签聚合或实验子集
- specialist 和 confusion cluster 要重新设计

当前状态补充：

- 已完成 `sd198_loader.py`
- 已接入 `case_loader.py`
- 已建立 `sd198_v1`
- 已提供 `sd198_full` 与 `sd198_grouped`
- 已修正 split 为 `sd198_balanced_v1`
- `sd198_full` 已被证明不适合作为当前主评测路线
- `sd198_grouped` 在 40-case compare 上已出现微弱正向信号，因此当前推荐继续沿 grouped 路线放大验证

### 暂缓：DermNet

原因：

- 当前本地只有索引与版权相关文件
- 缺少明确可直接评测的本地图像资产闭环
- 版权与来源问题不适合作为当前主接入线

## 9. 下一步建议

按当前工作区，更合理的下一步是：

1. `SD-198 grouped` 继续扩大 compare
2. 如有需要再设计 `SD-198 subset`
3. 再考虑下一条全新数据集
