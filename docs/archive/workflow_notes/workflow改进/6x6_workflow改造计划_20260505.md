# 6x6 Workflow 改造计划 2026-05-05

## 目标

把现有 6 条数据集 workflow 和新增模型 workflow 做成可共存的二维路由矩阵：

- 数据集维度继续由 `workflow_context["workflow_profile"]` 决定，不能破坏原来的 6 条线路。
- 模型维度作为叠加层记录在 `workflow_context["model_workflow_profile"]`，用于控制模型特定的简化、保守融合、检索深度、技能预算。
- 最终目标是稳定覆盖 6 个模型 × 6 个数据集 = 36 个 workflow cell，并让每个 cell 至少不低于 direct baseline，优先提升 top1、topk、malignant recall。

## 结果来源

主要查看了以下历史输出：

- `outputs/6x6_matrix_20260504_193716/summary.tsv`
- `outputs/6x6_matrix_20260504_193716/*/*/compare/compare_agent_vs_qwen_*.json`
- `outputs/6x6_matrix_20260504_193621/summary.tsv`
- `outputs/6x6_matrix_20260504_193621/*/*/compare/compare_agent_vs_qwen_*.json`

注意：这不是完整 36 格有效结果。SCIN、SD198 多数是运行/数据接入失败，不应当直接解释成 workflow 效果差。

## 运行失败问题清单

这些先按实验基础设施修，不作为 workflow 负收益判断。

| 问题 | 现象 | 影响 cell | 改造任务 |
|---|---|---|---|
| SCIN bootstrap index 不匹配 | `case-index xxxx out of range for 11 rows` | qwen/skinvl/llama 等 SCIN | 统一 split index 和 runtime loader index，bootstrap 输出必须是 `data-root` 可消费的局部 index 或 case_id |
| SD198 data root 错误 | `No CSV metadata file found under /root/DermAgent/data/sd198` | qwen/skinvl/llama 等 SD198 | runner 改用实际 SD198 runtime root，或让 `case_loader` 自动委派 `sd198_loader` |
| Llama SCIN timeout | `openai.APITimeoutError` | llama/scin | SCIN + Llama 增加 timeout/retry，先做 3-case smoke 再进 30-case |
| MedGemma/DermatoLlama 缺完整 30-case 矩阵 | 完整 6x6 输出没有有效 compare | medgemma、dermatollama 多数 cell | 先补跑 smoke，再补完整矩阵，不进入 workflow 调参结论 |

## Workflow 改造优先级

### P0. SkinVL 简化直连 workflow

涉及 cell：

- SkinVL × `clinical_full_taxonomy_lesion_workflow`：PAD20，严重下降。
- SkinVL × `image_archive_full_taxonomy_lesion_workflow`：ISIC2019，严重下降。

观察：

- SkinVL 的 `initial_perception` 经常为空，PAD20/ISIC2019 中大量 `image_summary=""`、`ddx_candidates=[]`。
- Agent 证据包文本被 SkinVL 当成诊断输出的一部分，出现大量反斜杠、retrieval JSON 片段、skill retrieval 文本进入 final diagnosis。
- PAD20 malignant recall 从 0.625 掉到 0.0，说明复杂证据/多步推理对 SkinVL 是强干扰。

改造清单：

- [ ] `SkinVL-MM` 默认使用 `direct_baseline_workflow` 叠加层：关闭 experience retrieval。
- [ ] SkinVL 禁用 specialist skills：`mel_nev_specialist_skill`、`ack_scc_specialist_skill`、`benign_mimic_specialist_skill`。
- [ ] SkinVL final 阶段优先走 baseline 或极简 evidence：只保留 `baseline_diagnosis`、label-space hint、最多 2 条短 observation。
- [ ] SkinVL evidence package 增加最大字符预算，例如 `max_total_chars <= 1200`，禁止 raw JSON/retrieval record 进入最终提示。
- [ ] SkinVL 输出解析增加 hard guard：final diagnosis 不允许包含 `{`、`source_id`、`retrieval_score`、大量反斜杠；触发后回退到 baseline。
- [ ] 对 SkinVL × HAM10000 保持观察，不强行引入复杂 DermAgent；当前 baseline 和 agent 都低，先避免负收益。

验收标准：

- SkinVL × PAD20：agent top1 不低于 0.20，malignant recall 不低于 0.625。
- SkinVL × ISIC2019：agent top1/topk 不低于 baseline，malignant recall 不再从 1.0 掉到 0。
- 任一 SkinVL cell 中 malformed final diagnosis 数量为 0。

### P0. Llama 图像档案 workflow 保守化

涉及 cell：

- Llama × `image_archive_full_taxonomy_lesion_workflow`：ISIC2019。

观察：

- Llama ISIC2019 top1 0.233 → 0.133，topk 0.367 → 0.133，malignant recall 0.368 → 0。
- 输出偏向 Seborrheic Keratosis，部分 final diagnosis 带 Markdown 格式，说明 evidence 可能把模型拉向良性固定模式。

改造清单：

- [ ] 给 Llama 添加 `conservative_archive_workflow` 模型叠加层。
- [ ] ISIC2019 + Llama 中降低 benign-mimic 和 generic exclusion 证据权重，避免统一漂移到 BKL/SEK。
- [ ] final fusion 对 Llama 开启 baseline anchoring：只有 agent evidence 明确支持时才改 baseline top1。
- [ ] 针对 malignant candidate 在 baseline top-k 中出现的 case，保留 malignant recall guard，不允许 agent 完全移除 malignant 标签。
- [ ] Llama final 输出解析去 Markdown：`**Final Diagnosis:**` 这类文本需要结构化清洗或回退。

验收标准：

- Llama × ISIC2019：top1 delta >= 0，topk delta >= 0，malignant recall delta >= 0。
- final diagnosis 结构化失败率为 0。

### P1. Llama PAD20 top1 重排

涉及 cell：

- Llama × `clinical_full_taxonomy_lesion_workflow`：PAD20。

观察：

- top1 0.433 → 0.200 下降明显。
- topk 0.467 → 0.667 上升，malignant recall 不变。
- 说明 agent 有把正确类别放进候选集的能力，但 final top1 排序或 conservative fusion 决策不好。

改造清单：

- [ ] 增加 PAD20 + Llama 的 top1 rerank guard：当 baseline top1 在 agent topk 中且 agent evidence 强度不足，不替换 baseline top1。
- [ ] 将 `clinical_metadata_reasoning` 证据和 lesion morphology 分开计分，避免 itch/elevation 等 metadata 过度推翻图像主诊断。
- [ ] 对 SCC/BCC/ACK 三类角化病变加入 pairwise rerank，不让 broad SCC 默认压过 BCC/ACK。
- [ ] 对 PAD20 输出 label 做 canonical normalization，避免长病名和短码混用导致评估损失。

验收标准：

- Llama × PAD20：top1 不低于 0.433，同时保留 topk >= 0.667。

### P1. Qwen PAD20 风险召回修复

涉及 cell：

- Qwen × `clinical_full_taxonomy_lesion_workflow`：PAD20。

观察：

- top1 从 0.200 到 0.267，整体正向。
- malignant recall 从 0.667 掉到 0.542，风险召回下降。

改造清单：

- [ ] 保留当前 Qwen PAD20 workflow 主体，不做大改。
- [ ] 加入 malignant recall guard：baseline 或 agent top-k 包含 malignant，且 evidence 不足以支持 benign overwrite 时，不允许最终落到 benign。
- [ ] 对 NEV/SEK 覆盖 BCC/ACK/SCC 的 case 做错误清单，检查 benign mimic evidence 是否过强。
- [ ] 限制 benign evidence 在 PAD20 full-taxonomy lesion workflow 中的最终覆盖权重。

验收标准：

- Qwen × PAD20：top1 维持 >= 0.267，malignant recall 回到 >= 0.667。

### P2. SCIN / SD198 数据 workflow 恢复

涉及 cell：

- `family_routing_workflow`
- `coarse_taxonomy_workflow`
- SCIN、SD198 上所有模型。

改造清单：

- [ ] 修复 SCIN split 到 runtime case index 的映射，避免 11 行 filtered metadata 被大 index 调用。
- [ ] 修复 SD198 runtime root，补充 `data/sd198` 目录结构检查和错误提示。
- [ ] 为 SCIN/SD198 先运行 `1 model × 2 dataset × 3 case` smoke。
- [ ] smoke 通过后再跑 qwen/skinvl/llama/hulumed 的 30-case compare。
- [ ] SCIN/SD198 有完整结果后再决定是否调 family/coarse workflow，不提前根据失败日志调参。

验收标准：

- SCIN、SD198 每个模型至少能完成 bootstrap + compare。
- result JSON 中 case 数和 split JSON case 数一致。

### P2. 正向 cell 冻结保护

涉及 cell：

- Qwen × Xiangya
- Hulumed × ISIC2019
- Hulumed × HAM10000
- Qwen × HAM10000
- Qwen × ISIC2019

改造清单：

- [ ] 为这些 cell 建立 regression baseline，不随 P0/P1 改造改变默认行为。
- [ ] 每次修改 SkinVL/Llama/Qwen-PAD20 逻辑后，至少跑这些 cell 的 3-case smoke。
- [ ] 如果正向 cell 指标下降，优先用模型叠加层隔离，而不是改全局 workflow。

验收标准：

- 正向 cell 的 top1/topk/malignant recall 不低于当前历史结果。

## 实施顺序

1. 修复矩阵结果解析和失败标注。
   - 产出：`outputs/.../matrix_metrics.tsv` 或等价 JSON。
   - 目的：每次改造后自动看到 36 格变化。

2. 固化 SkinVL 简化路由。
   - 先做 PAD20/ISIC2019 3-case smoke。
   - 再跑 PAD20/ISIC2019 30-case compare。

3. 修 Llama ISIC2019。
   - 先做输出结构化和 baseline anchoring。
   - 再跑 30-case compare。

4. 修 Llama PAD20 top1 rerank。
   - 保留 topk 正向信号，只调 final top1 selection。

5. 修 Qwen PAD20 malignant recall guard。
   - 不改 Qwen 其他正向数据集的 workflow。

6. 恢复 SCIN/SD198 数据接入。
   - 完成后重新生成 36 格矩阵，再决定 family/coarse workflow 是否需要调参。

7. 补 MedGemma/DermatoLlama。
   - 先 smoke，后完整 compare。

## 不做的事

- 不把模型路由写死成 dataset 特例。
- 不覆盖 `workflow_context["workflow_profile"]`。
- 不因为 SkinVL 失败而削弱 Qwen/Hulumed 已经正向的全局 workflow。
- 不在 SCIN/SD198 跑通前对 family/coarse workflow 下结论。
